# N14 Control — согласованный объём и границы модулей

## Пожелания пользователя

1. Независимое от CoolerControl управление вентиляторами: редактируемые кривые,
   CPU/GPU/Mix и необходимые Functions с подтверждённой семантикой.
2. Настраиваемые профили питания. Составной профиль может задавать системный
   power profile, частоту панели, выбранный потолок частоты CPU/boost и отдельное
   разрешение Turbo Boost. Правила: сеть, аккумулятор, низкий заряд.
3. Подсветка клавиатуры в том же приложении.
4. RCU Lazy и дополнительные полезные оптимизации с проверкой доступности,
   объяснением последствий и возможностью отмены, без универсальной кнопки
   «включить все твики».
5. MSHybrid / iGPU-only / dGPU-only, если существует подтверждённый интерфейс
   BIOS/прошивки. Возможная перезагрузка должна быть явной.

Дополнительные функции можно добавлять после этих пунктов. Независимость — не
запрет взаимодействия: изменения должны согласовываться общим механизмом профилей
и единым владельцем каждого аппаратного интерфейса.

## Реализовано в 0.2

Актуализация 2026-10-31: native CPU/EC service и sampler реализованы; bounded live
CPU tach/target/keylight readback test предыдущего API пройден. Сейчас публичные
`AcquireEc`/`ReleaseEc` удалены: EC protocol 2 переносит authorization/preflight и
lease lifecycle внутрь сервиса. GUI/harness посылают provenance/command requests,
а не ownership operations. Новый контракт отдельно установлен и прошёл bounded
live validation: CPU tach `2900 → 4500` nominal RPM, 12/12 raw readbacks и точный
restore targets/keylight/mode. Это не полная thermal/load/sleep validation;
отдельная bounded load-попытка остановилась на EC transaction failure и не
считается thermal pass;
отдельный clean active-owner restart также прошёл с неизменным control state и
нулём автоматических Apply после restart по D-Bus audit. Не проверены in-flight
restart races, длительная нагрузка и физический sleep/resume.
Точные результаты — в `VALIDATION.md`. Перечень ниже сохраняет историю этапа 0.2.

- Схема 2, миграция 1 → 2 с резервной копией, до 16 именованных CPU/экран/питание
  пресетов, редактирование и явное ручное применение.
- Автовыбор составного пресета; исключение конкуренции со старыми простыми правилами.
- Отдельный CPU-only D-Bus-сервис с Polkit и ограниченной транзакцией sysfs.
- Диагностика доступности возможностей без вводящих в заблуждение переключателей.
- События подготовки ко сну и возобновления для правил и CPU-авторизации.

Установка/обновление сервисов требует отдельных прав администратора. Ранее
установленная версия не обновляется автоматически при сборке; bounded live test
не означает завершённой thermal/load/sleep validation.

## Следующий аппаратный этап

**Уточнение пользователя:** существующий функционал переносится строго как в
опубликованных исходниках GitHub. Точный эталон и границы:
[reference/PORTING.md](reference/PORTING.md), `reference/source-lock.json`.
Политика отказа не заменяется самовольно: сохраняется опубликованный вариант без
автоматической аварийной подстановки скорости вместе с его исходными рисками.

Перед передачей вентиляторов новому сервису требуется подтвердить соответствие:

- поведение при пропаже/устаревании температуры, частичной EC-записи, зависании
  процесса и завершении сервиса;
- возврат управления прошивке, ручные команды и правила восстановления после сна;
- сохранение последней команды по опубликованной политике: вентиляторы могут
  оставаться остановленными неограниченно долго; это не гарантия безопасности;
- процедуру единоличного владения EC, совместимость BIOS 2.07/EC и откат на
  действующий стек без параллельных контроллеров.

Контракт и implementation этого этапа зафиксированы в
[reference/EC_WRITER_DESIGN.md](reference/EC_WRITER_DESIGN.md). Metadata-only
probe по-прежнему не имеет операций записи, `flock` или device-open. Отдельный
offline RAII lease и fake broker тестируют `O_NOFOLLOW|O_CLOEXEC`, non-blocking
`flock`, provenance, partial-failure revoke и lock lifecycle. Предыдущий API и
установленный service-managed EC protocol 2 имеют отдельные bounded live receipts;
один clean active-owner restart проверен отдельно, но успешная длительная
нагрузка, sleep/resume и in-flight lifecycle races на физическом ноутбуке ещё не
проверены. После физического partial/uncertain EC результата исходные `42/42`
были восстановлены только отдельным явно запущенным fresh-provenance restore;
автоматического recovery write не было.
Команда `--ownership-preflight` выдаёт только deny-able JSON report; порядок
перехода к target-specific проверке зафиксирован в
`reference/N14_HARDWARE_VALIDATION.md` и не включает автоматическую остановку
существующего cooling stack.

Подсветка использует ту же сериализованную EC-очередь, что и вентиляторы:
её текущая процедура временно затрагивает режим вентиляторов.
CPU-сервис и EC broker используют отдельный root D-Bus service; EC permissions
выдаются отдельным Polkit action `org.n14control.modify-ec`.
## Не обещано без исследования

- Программная доступность всех трёх MUX-режимов на данном BIOS.
- Возможность менять RCU Lazy без перезагрузки при параметре ядра только для чтения.
- Экономия батареи и сохранение D3cold без физических испытаний.
- Точная совместимость предпросмотра с CoolerControl Standard.
